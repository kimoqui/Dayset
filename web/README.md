# DaySet 로컬 버전 (0.2.0)

자동으로 짜주는 일정으로 편하게 생활습관 잡기. 디자인은 시안 B '나이트 링'(어두운 남색 + 앰버, 24시간 링 홈)입니다.
서버 없이 브라우저에서 동작하는 로컬 앱입니다. 기록은 그 브라우저 안(localStorage)에만 저장됩니다.

## 실행 방법

### 1. 바로 열기 (설치 없음)
`DaySet.html`을 더블클릭하면 Chrome·Edge·Safari에서 열립니다.
- **시작하기**: 입력 없이 바로 시작합니다(아래 '2일 관찰').
- **예시 데이터로 둘러보기**: 3주치 기록이 채워진 상태로 모든 화면을 볼 수 있습니다.
- **기록 없이 바로 설정하기**: 기상·식사·운동 시간을 직접 입력하고 시작합니다.

### 2일 관찰 (처음 시작)
1. **1일차 · 기록만**: 설정 없이 '지금' 버튼으로 하루를 그대로 기록합니다. 오후 3시 이후에 시작하면 다음 날이 1일차입니다(그날 밤 '수면'만 누르면 됩니다).
   - 이때 안내는 강조 팝업으로 10초 동안 뜨고 저절로 닫힙니다. 밤 10시가 넘어도 '수면'을 누르지 않았으면 한 번 더 뜹니다('지금 잘게요' 버튼 포함).
2. **1일차 저녁 · 내 하루 보기**: 기록한 기상·식사·운동·업무 시각이 나옵니다. 바꾸고 싶은 시각만 고치고 '이대로 내일 일정 만들기'를 누릅니다.
   - 기상을 30분 넘게 바꾸면 한 번에 바꾸지 않고 매주 30분씩 옮깁니다.
   - 업무 시작 시각부터 3시간을 집중 시간대로 둡니다.
3. **2일차 · 첫 일정**: 알람과 일정이 자동으로 짜인 첫날입니다. 저녁 확인에서 정한 시각과 20분 넘게 어긋난 습관만 "옮길까요?"로 다시 묻고 관찰을 끝냅니다.
- 이동 시간은 처음에 묻지 않고, 첫 캘린더 일정을 넣을 때 한 번만 묻습니다.

### 2. 개발 모드 (코드 수정용)
Node.js 20 이상이 필요합니다.
```bash
npm install
npm run dev          # http://localhost:5173
npm test             # 엔진·흐름 테스트 58개
npm run build:single # dist-single/index.html 한 파일로 빌드
npm run build        # dist/ (웹 서버에 올리는 버전, 오프라인 캐시 포함)
```

### 3. 휴대폰에서 쓰기
`npm run build`로 만든 `dist/` 폴더를 https 웹 호스팅(예: Netlify, Vercel, GitHub Pages)에 올린 뒤
휴대폰 브라우저에서 열고 **홈 화면에 추가**를 누르면 앱처럼 실행됩니다.

## 들어 있는 기능

| 화면 | 기능 |
| --- | --- |
| 홈 | '지금' 버튼 5개(수면·식사·업무·운동·휴식), 5초 되돌리기, 10분 안 복귀 시 기록 합치기, 다음 일정·다음 알람, 코칭 제안(바꾸기/그대로 두기) |
| 일정 | 오늘·내일 자동 일정, 알람 시각과 근거, 지난 일정의 달성·놓침 표시, 캘린더 일정 직접 입력, 남은 시간 다시 짜기 |
| 할 일 | 입력은 이름·종류·걸리는 시간만. 손잡이를 끌어(또는 위아래 화살표) 우선순위를 정하고, 위에 있는 일부터 빈 시간 75%까지 50분 조각으로 자동 배치. 할 일을 넣거나 순서를 바꾸거나 끝내면 오늘 남은 일정(과 확정한 내일 일정)을 바로 다시 짜고, 어디에 넣었는지 알려 줌. 15초 안에 되돌리기 |
| 걸리는 시간 자동 보정 | 끝낼 때 예상 대비 실제로 쓴 시간(반영한 조각 + 오늘 지난 조각)을 기록. 같은 이름 2건 또는 같은 종류 3건부터 실제/예상 중앙값(0.5~2배)으로 일정에 잡음. 적은 예상 시간은 그대로 두고 '→ 일정엔 1시간 20분'으로 표시. 잡은 시간을 다 쓰면 '끝났어요 / +30분 / +1시간'을 물음(할 일 화면·저녁 확인). 설정에서 끄기 |
| 캘린더 가져오기 | 구글 캘린더 직접 연결(읽기 전용, 켜 둔 캘린더 최대 10개, 30분마다·화면 다시 볼 때·인터넷 복구 때 자동 동기화) 또는 .ics 파일(반복·빠진 날·바뀐 날·시간대 처리). 앞으로 2주, 같은 캘린더는 통째로 바꿈. 가져오면 남은 일정을 바로 다시 짬 |
| AI 순서 추천 | 순서 바꾸기·먼저 끝낸 일을 기기 안에서 배워(3일·6건 이상) 추천 순서와 이유(종류·길이·오래된 일)를 제안. '이 순서로 바꾸기' 또는 '지금 순서 유지' |
| 기록 | 주간 셋 데이·습관별 달성률·날짜별 막대, 월간 셋 데이 캘린더(날짜 숫자 없음, 쉬는 날 점), 기상 단계적 교정 현황, 오늘 기록 지우기 |
| 저녁 확인 | 자동 기록 목록, 기록 없는 일정만 '했어요/못 했어요(이유)/쉬는 날', 쉬는 날 표시, 내일 일정 확정 |
| 알람 | 기상 알람(끄기 = 기상 기록, 5분 미루기 횟수 기록), 취침 알림(잘게요 = 수면 기록), 마무리 알림, 코칭으로 켠 습관 미리 알림 |
| 설정(아래 탭) | 목표·습관 시간·준비/이동·집중 시간대, 단계적 교정 시작/끄기, 테마(나이트·밝게·기기 설정), 백업 내보내기/불러오기, 시험용 시각 |
| 화면 전환 | 홈 오른쪽 위 버튼으로 나이트 ↔ 밝게를 바로 바꿈 |
| 연속 기록 | 듀오링고식 '며칠 연속 셋 데이'(쉬는 날은 끊기지 않음), 최고 기록, 홈 불꽃 칩, 3·7·14·30·50·100일 기념 축하 |
| 공유 | 카카오톡(정사각 카드 + 친구 코드 문구), 인스타 스토리(세로 카드). 휴대폰은 공유 창, 데스크톱은 이미지 저장 + 문구 복사 |
| 소셜 탭 | 기록 탭과 분리. 연속 기록 카드 + 카톡·인스타 공유, 근처(익명)·친구 순위 |
| 처음 목표 정하기 | 첫 접속: 바꾸고 싶은 것(일찍 일어나기·충분히 자기·아침·운동·할 일) 고르기 + 목표 기상·수면·운동 시간 → 동의 → 알림 켜기 → 첫날 기록. 1일차 리뷰에서 이 목표가 기본값 |
| 동의 | [필수] 생활 기록 수집·이용, [선택] 베타 지표 내보내기. 동의 없이는 기록 화면으로 들어가지 않음(예전 데이터도 동의 화면부터). 설정에서 다시 보기·거두기(기록 지움) |
| 일정 체크 팝업 | 탭 위에 늘 떠 있음. 일정이 시작됐는데 기록이 없으면 펼쳐서 '식사 시작했어요 / 지금은 안 해요', 일정이 끝났는데 기록이 이어지면 '끝났어요', 기록 중이면 작은 띠로 지금·다음 일정 |
| 알림 | 알림 권한 + 푸시 토큰(VITE_VAPID_PUBLIC_KEY가 있을 때). 지금 일정 알림을 띄워 두고(같은 tag 1개), 기록할 때 소리로 알림. 설치형(https)에서는 알림의 '기록하기·지금은 안 해요' 버튼으로 바로 기록 |
| 베타 지표 | 쓴 날·활성화(2일 관찰 완료)·1/7/14일 유지·주별 셋 데이·기능 사용 횟수·설문·불편 신고를 기기에 쌓고 JSON으로 내보내기(미리 보기). 이름·기록 시각·제목·위치는 넣지 않음 |
| 설문·불편 신고 | 7일째·28일째 '없어지면 얼마나 아쉬운지' 설문(홈 카드), 설정 → 불편 신고·의견 |
| 근처 순위(익명) | 프리뷰 빌드는 위치를 읽지 않고 QR·코드 교환만(VITE_NEARBY_LOCATION=on이면 켤 때만 위치를 읽어 약 2km 칸으로 뭉갬). 실명 대신 기기 고정 익명 별명. 로컬 버전은 QR·코드를 직접 주고받아 순위에 올림(카메라 QR 읽기는 지원 브라우저만, 아니면 붙여 넣기). 앱 버전에서는 같은 칸 사람들이 서버로 자동 표시. 예시 데이터는 '예시' 표시 |
| 친구 순위 | 친구 코드(DS1-…)를 주고받아 이번 주 셋 데이 순위. 코드를 받을 때 갱신(앱 버전에서 실시간) |
| 링 눌러 보기 | 홈 24시간 링을 누르면 그 시각·일정·시간대·걸린 시간, 실제 기록을 가운데에 보여 줌(6초 뒤 지금으로) |
| 일정 자동 생성 시연 | 일정 탭 '시연' 또는 설정. 5가지 상황(평소·아침 회의·점심 약속·할 일 폭탄·짧은 수면)으로 기상→취침→캘린더→습관→빈 시간→할 일→알람(→코칭) 단계를 재생, 평소와 비교. 내 기록은 바뀌지 않음 |
| 캘린더 추가 예시안 | A 한 줄 입력("내일 오전 9시 팀 회의"), B 타임라인에서 빈 칸 누르기, C 버튼만으로. 셋 다 '넣으면 일정이 어떻게 바뀌는지' 미리보기 |
| 모션 | 좌우로 밀어 옆 탭 이동(손가락을 따라오고, 22% 이상 밀거나 빠르게 넘기면 전환), 탭 전환 방향 모션, 스위치 손잡이 늘어남·튕김, 버튼 눌림, 세그먼트 표시 이동, 시트·안내 띠 슬라이드. 기기의 '동작 줄이기' 설정을 따름 |

엔진 규칙(일정 생성, '지금' 버튼, 달성 판정, 셋 데이, 단계적 교정, 코칭 R1~R9)은 Flutter 버전(`dayset/lib/core`)과 같은 규칙을
TypeScript로 옮긴 것이고, 같은 테스트를 통과합니다.

## 로컬 버전의 한계 (앱 버전에서 해결)
- **알람은 이 화면이 열려 있을 때만 울립니다.** 휴대폰 기본 알람 연동(iOS AlarmKit·단축어, 안드로이드 AlarmClock)은 앱 버전에서 합니다.
- 구글 연결은 https 주소나 localhost에서만 됩니다(파일로 열면 .ics 가져오기). 구글 클라이언트 ID가 필요하고(`VITE_GOOGLE_CLIENT_ID` 또는 캘린더 가져오기 → 개발자 설정), 토큰은 1시간짜리라 만료되면 '다시 연결'을 누릅니다. 앱 버전은 휴대폰 캘린더를 직접 읽고 서버가 계속 동기화합니다.
- 홈 화면 위젯, 건강 앱(워치 수면) 연동, 대화형 비서(AI)는 앱 버전 범위입니다.
- 기록은 이 브라우저에만 있습니다. 다른 기기로 옮길 때는 설정 → 백업 내보내기/불러오기를 씁니다.

## 비정상 상황 대처
| 상황 | 대처 |
|---|---|
| .ics가 아닌 파일, 5MB 넘는 파일, 읽다 실패 | 가져오지 않고 이유와 다음 행동을 안내 |
| 2주 안에 시각 있는 일정이 0개인 파일로 이미 가져온 캘린더를 바꾸려 함 | 지우기 전에 확인('그대로 두기'가 기본) |
| 직접 넣은 일정과 같은 일정(제목·시각) | 중복으로 보고 가져오지 않음, 몇 개 뺐는지 알림 |
| 하루 종일·한가함·취소·12시간 넘는 일정 | 일정 배치에서 빼고 개수 알림 |
| 한 캘린더 400개 초과 | 잘라서 저장 공간 보호 |
| 인터넷 끊김, 구글 응답 실패 | 이전에 가져온 일정은 그대로 두고 그것으로 짬. 인터넷이 돌아오면 자동 재시도 |
| 구글 연결 만료·거절·팝업 차단 | 이전 일정 유지, 일정 화면에 배너와 '다시 연결' |
| 하루 넘게 동기화 못 함 | '오래됨' 안내 |
| 할 일을 하는 도중 순서·할 일이 바뀜 | 지금 하는 조각은 끊지 않고 그 뒤부터 다시 짬(그 일을 끝내면 바로 끊음) |
| 다시 짰더니 빈 시간이 모자람 | 밀려난 할 일 이름을 알림 |
| 잘못 누름 | 할 일·캘린더 변경은 15초 안에 일정까지 함께 되돌리기, 완료 취소 시 보정 기록도 지움 |
| 5분 안 돼 체크(실수), 며칠 묵혀 실제 시간이 튐(1/3~3배 밖) | 보정에 쓰지 않음 |
| 저장 공간 가득 참 | 홈에 원인과 정리 방법 표시 |
| 저장된 데이터가 깨짐 | 지우지 않고 따로 보관한 뒤 새로 시작, 설정 → 데이터에서 내려받기 |
| 백업 불러오기 | 불러오기 전 기록을 보관, '되돌리기' 가능(최근 3개) |

## 프리뷰 배포
1. `npm run build` → `dist/` 폴더를 https 정적 호스팅에 올린다(홈 화면 추가·알림 버튼·구글 연결은 https에서만).
2. 빌드할 때 넣는 값(`.env`): `VITE_GOOGLE_CLIENT_ID`(구글 캘린더), `VITE_VAPID_PUBLIC_KEY`(푸시 토큰, 서버가 있을 때), `VITE_NEARBY_LOCATION=on`(위치 신고·검토 뒤에만).
3. 파일 하나로 시연할 때는 `npm run build:single` → `dist-single/index.html`(알림 버튼·구글 연결 제외).

## 시험해 보기
- 주소 뒤에 `?t=2026-10-19T06:59`를 붙이면 그 시각부터 시계가 흐릅니다(알람·저녁 확인 흐름 확인용).
- 설정 → 시험용 시각에서도 바꿀 수 있습니다. 시험 뒤에는 **실제 시각으로 되돌리기**를 누르세요.

## 폴더 구조
```
src/engine/   도메인 모델과 엔진(화면과 무관한 순수 코드) + 테스트
src/app/      기기 저장(state), 계산(derive), 동작(store), 예시 데이터(seed) + 흐름 테스트
src/ui/       화면(screens), 공통 부품(kit), 알람 화면, 스타일 토큰(styles.css)
public/       설치형 앱 정보(manifest), 오프라인 캐시(sw.js), 아이콘
```

## 앱으로 옮기는 길
1. **같은 코드를 앱으로 감싸기(Capacitor)**: 지금 웹 코드를 그대로 iOS·안드로이드 앱으로 만듭니다. 알람·위젯·캘린더·건강 연동은 네이티브 플러그인으로 붙입니다. 가장 빠릅니다.
2. **Flutter 버전으로 이어가기**: `dayset/`의 Flutter 코드가 같은 엔진 규칙을 갖고 있습니다. 로컬 버전에서 확인한 화면·흐름을 Flutter 화면에 옮깁니다. 네이티브 알람·위젯 코드는 이미 `dayset/native/`에 있습니다.

어느 쪽이든 `src/app/state.ts`의 저장 구조가 기기 DB 테이블 설계의 기준이 되고, 백업 JSON으로 로컬 버전 기록을 옮길 수 있습니다.
